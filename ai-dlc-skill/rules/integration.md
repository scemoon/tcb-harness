# Integration Rules (INT-*)

Rules for cross-component contract discipline. Apply to any change that touches more than one component, or that introduces / changes a public API or async event.

## INT-001: Contract as Source of Truth

**Severity:** MUST

**Description:** All cross-component public APIs and async events MUST be defined in `contracts/` (OpenAPI 3.1 for REST, AsyncAPI 3.0 for events, GraphQL SDL for GraphQL) and tagged with the `INT-FR-*` they implement. Hand-written types in component code that diverge from the contract are forbidden.

**Valid:** `contracts/api/auth.yaml` defines `POST /auth/login`; `apps/backend/src/auth/` implements it; `apps/web/src/api/client.ts` uses types generated from the same file.

**Invalid:** A `User` type defined twice — once in `apps/backend/src/models/user.py` and once in `apps/web/src/types/user.ts` — with no contract file linking them.

## INT-002: Backward-Compatibility by Default

**Severity:** MUST

**Description:** Contract changes MUST be backward-compatible by default. A change is **breaking** if it:
- removes a field, endpoint, or message
- changes a field's type
- changes an HTTP status code
- renames a field, endpoint, or message
- adds a required field to an existing request
- narrows a value range (e.g. `string` → `enum`)

A breaking change is BLOCKED until a human approves a MAJOR version bump and a migration note is added to `contracts/CHANGELOG.md`. `tools/contract_diff.py` is the authoritative detector.

**Valid (additive, MINOR):** adding a new optional response field, adding a new endpoint, adding a new message to a channel.

**Valid (breaking, MAJOR with approval):** removing a deprecated field, with `contracts/CHANGELOG.md` documenting the migration.

**Invalid:** A breaking change merged without a `CHANGELOG.md` entry and human sign-off; or a non-breaking change labeled as breaking (or vice versa) to bypass review.

## INT-003: Generated Shared Types

**Severity:** MUST

**Description:** `packages/shared/` is generated from `contracts/`. Component code MUST import from `packages/shared/`, not redefine types. CI MUST fail the build if `packages/shared/` is out of date relative to `contracts/`.

**Valid:**
```bash
tools/generate_shared.py
git diff --exit-code packages/shared/  # CI: must be clean after generation
```

**Invalid:** Hand-edited files under `packages/shared/`; or a component redefining `LoginRequest` in its own `src/types/`.

## INT-004: Contract Tests at INT FR Level

**Severity:** MUST

**Description:** Every `INT-FR-*` MUST have contract tests in `tests/contract/` that verify the contract shape, the request/response schema, and the error contract. Contract tests use the generated `packages/shared/` types and are provider-agnostic (no network calls to the real provider).

**Valid:** `tests/contract/test_auth.py` uses a fake provider to assert the request payload matches the OpenAPI schema, the response matches the schema, and the error code matches the documented error contract.

**Invalid:** Contract tests that call the real production backend; or contract tests that only check status codes without asserting schema.

## INT-005: Cross-Stack Feature Coverage

**Severity:** MUST

**Description:** Every `INT-FR-*` MUST have a corresponding scenario in `features/cross-stack/` (≥3 scenarios: positive, negative, edge). The cross-stack scenario is implemented as an e2e test in `tests/cross-stack/` and runs against the unified `STACK_URL`.

**Valid:** `features/cross-stack/auth/login.feature` declares `@INT-FR-001` with three scenarios; `tests/cross-stack/test_login.py` implements them and runs against the deployed stack.

**Invalid:** An `INT-FR-*` without a `features/cross-stack/*.feature` entry, or a cross-stack feature file that is never wired to a test in `tests/cross-stack/`.

## INT-006: Contract Diff Artifact

**Severity:** MUST

**Description:** Every change that modifies a contract MUST produce `openspec/changes/{id}/contract-diff.md` summarizing the diff, the breaking-change status, and the sign-off. The artifact is required to pass the Verify phase.

**Valid:** `contract-diff.md` is generated by `tools/contract_diff.py` and lists added/removed/changed fields with the per-component review status.

**Invalid:** A contract change merged without `contract-diff.md`, or `contract-diff.md` left as the empty template.
